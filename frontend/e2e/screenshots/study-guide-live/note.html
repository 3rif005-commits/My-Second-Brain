Reinforcement Learning Fundamentals

Overview
  • What: Establishing the core principle that agents learn optimal behavior through interaction with an environment, using only reward signals—no labeled answers.
  • How it breaks down:
    • Three branches of machine learning — how RL differs from supervised and unsupervised learning
    • Core components and the "no teacher" principle — what makes RL unique and what defines the learning problem
    • When to use RL — applications where the exploration-exploitation trade-off matters
  • Takeaway: RL is the only branch where the agent must discover the right answer by trial and error; this freedom from a labeled ground truth is both its defining feature and its core challenge.

Three branches of machine learning

Supervised Learning

Supervised Learning: Learning to map input to output using labeled examples (answer key provided).

The learner receives correct labels paired with inputs and learns to predict outputs for new inputs. Analogous to a student with an answer key.

Unsupervised Learning

Unsupervised Learning: Learning hidden patterns in data without labels.

The learner finds structure and clusters in data with no ground truth guidance. Analogous to an explorer finding tribes by observing the landscape.

Reinforcement Learning

Reinforcement Learning: Learning what action to take in order to maximize cumulative reward, using only reward and punishment feedback.

The learner receives sparse, delayed feedback signals (rewards or penalties) and must discover which actions lead to better long-term outcomes. Analogous to a pet learning tricks for treats—no map, no instructions, only reinforcement.

Core components and the "no teacher" principle

The five core components

RL System: An agent, environment, actions, states, and rewards that form a complete feedback loop.

  • Agent: The learner that makes decisions and learns from experience.
  • Environment: The world the agent interacts with; it responds to actions and produces rewards.
  • Action: A decision the agent can take (e.g., move up, down, left, right).
  • State: A snapshot of the environment describing where the agent is and what it perceives.
  • Reward: A feedback signal indicating how good or bad an outcome is; R(s) is the reward received for arriving in state s.
The "no teacher" principle

No Teacher: Unlike supervised learning, no external agent provides correct answers; the agent learns only from reward and penalty signals as it explores.

  • Exploration scenario: The agent takes actions in an unknown environment with no map or instructions.
  • Feedback signals: Small incremental signals (warmer → +1, colder → −1) guide exploration; large signals mark major outcomes (candy → large +, lemon → large −).
  • Learning mechanism: The agent accumulates rewards over time and gradually learns which actions lead to better outcomes, with no correct path given in advance.
  • Core insight: The agent improves by experience and feedback, not by following a provided solution.

When to use reinforcement learning

Applications suited to RL

RL applicability: RL is the right choice when no fixed "correct" label exists, outcomes depend on sequential decisions, or the environment is adaptive or unknown.

ApplicationWhy RL?
Self-driving carsNo "correct" steering label for every situation
Game AI (AlphaGo, Chess)Opponent adapts, no fixed answer key
Robot navigationEnvironment is unknown or changing
Recommendation systemsUser feedback is sequential, not one-shot
The exploration-exploitation dilemma

Exploration-Exploitation Trade-off: The fundamental tension between trying new actions that might be better (exploration) and repeating actions known to work (exploitation).

  • Exploitation: Choosing the action with the highest known Q-value (greedy choice based on current knowledge).
  • Exploration: Choosing a random action to discover potentially better paths not yet discovered.
  • The dilemma: Too much exploitation means missing better strategies; too much exploration means wasting time on suboptimal actions.

In practice, early episodes favor exploration (random choices) to discover the landscape; later episodes favor exploitation (greedy choices) to maximize reward using learned knowledge.

Q-Learning and Value Functions

Overview
  • What: Building a memory system (Q-table) that stores the long-term value of state-action pairs, and using the Bellman equation to learn those values iteratively.
  • How it breaks down:
    • Value functions and Q-values — what the agent learns to store and why
    • The Bellman equation and observed Q-value — how to compute the ground-truth value of a state-action pair
    • Temporal difference error and the update rule — how to close the gap between current estimate and observed value
    • Learning parameters — discount factor γ and learning rate α
    • Episodes and convergence — why one episode is not enough and when learning is complete
  • Takeaway: Q-learning works by repeatedly observing transitions, computing what the value "should" be, comparing it to what the agent thought, and adjusting incrementally toward truth—a process that converges to the optimal policy only with multiple episodes of experience.

Value functions and Q-values

Value function V(s)

State Value Function V(s): A scalar estimate of how good it is to be in state s, considering all possible future rewards from that state onward.

  • Input: A state s.
  • Output: A number indicating the total expected reward if the agent is in state s and acts optimally from that point.
  • Use: Evaluates the state alone, without reference to the action that led there.
State-action value function Q(s,a)

Q-value (state-action value): A scalar estimate of how good it is to take action a in state s, considering all possible future rewards from that transition onward.

  • Input: A state s and an action a.
  • Output: A number indicating the total expected reward if the agent takes action a in state s and acts optimally thereafter.
  • Representation: Stored in a table with rows = states, columns = actions, cells = Q-values.
  • Goal: Q-learning seeks to learn Q-values that maximize total cumulative reward.

Q(s,a) is the primary data structure in Q-learning. The agent stores and updates Q-values for every (state, action) pair it experiences. The final learned Q-table encodes the optimal policy: from any state, choose the action with the highest Q-value.

The Bellman equation and observed Q-value

Bellman equation

Bellman Equation: A recursive formula that expresses the value of a state-action pair as the immediate reward plus the discounted value of the best action in the next state.

Observed Q-value (Bellman form)

Q_{\text{observed}}(s, a) = R(s') + \gamma \max_{a'} Q(s', a')
  • s: Current state.
  • a: Action taken in state s.
  • s': Next state (the state the agent arrives in after taking action a).
  • R(s'): Immediate reward received for arriving in state s'.
  • γ (gamma): Discount factor; controls how much the agent values future rewards relative to immediate rewards.
  • maxa' Q(s', a'): The maximum Q-value available in the next state (the best action the agent can take from s').

The Bellman equation decomposes the total future reward into two parts: what you get right now (R) and what you'll get later (discounted by γ and the next state's best option). This recursive structure is the foundation of all value-based learning.

Discount factor γ

Discount Factor γ (gamma): A parameter (0 ≤ γ ≤ 1) that controls how much the agent values future rewards compared to immediate rewards.

  • γ = 0: Robot cares only about immediate reward; future is irrelevant.
  • γ = 0.5: Future rewards matter half as much as immediate rewards.
  • γ = 0.9: Future rewards matter, but slightly less than today's rewards (realistic for most problems).
  • γ = 1: Robot values future rewards equally to immediate rewards (only valid for finite-horizon problems).

A higher γ makes the agent more tolerant of short-term negative rewards when future rewards are promising. This allows the agent to persist through costs to reach a valuable goal. Lower γ makes the agent myopic, prioritizing immediate gains.

Worked example: S5 → S6 with γ = 0.1 vs γ = 0.9

Both transitions use the same state pair and reward but show how γ changes the interpretation of future value.

With γ = 0.1, the negative immediate cost dominates, yielding a negative Q-value. With γ = 0.9, the strong future reward outweighs the immediate cost, yielding a positive Q-value. The same transition is interpreted very differently based on how much the agent cares about the future.

Temporal difference error and the update rule

Temporal difference error (TDE)

Temporal Difference Error: The gap between what the agent predicted the value would be and what it actually observed; the prediction error that drives learning.

Temporal Difference Error

\text{TDE} = Q_{\text{observed}}(s, a) - Q_{\text{expected}}(s, a)
  • Q_observed: The true value computed using the Bellman equation.
  • Q_expected: The value currently stored in the Q-table for (s, a).
  • Positive TDE: The true value is higher than expected; the agent was too pessimistic.
  • Negative TDE: The true value is lower than expected; the agent was too optimistic.

TDE is the signal that drives all updates in Q-learning. The update rule uses TDE to move the stored Q-value toward the observed value. No prediction error → no learning.

Learning rate α and the update rule

Update Rule: A formula that adjusts the Q-value by moving it incrementally toward the observed value, scaled by a learning rate.

Q-value update

Q(s, a) \leftarrow Q(s, a) + \alpha \times \text{TDE}
  • Q(s, a): The Q-value to update.
  • α (alpha): Learning rate; controls the size of the update step (0 < α ≤ 1).
  • TDE: Temporal Difference Error (observed − expected).

Learning rate α tuning:

  • α too small: Learning is slow; many episodes needed for convergence.
  • α too large: Updates overshoot; Q-values oscillate and may not converge.
  • Typical α: 0.1 balances steady learning with stability.

Episodes and convergence

Episode definition

Episode: One complete run from a starting state to a terminal state (goal, failure, or timeout).

  • An episode represents a single trial or game.
  • Examples: one playthrough of a game, one run of a robot from start to target.
  • Within one episode, the agent takes a sequence of actions and receives rewards.
Why one episode is insufficient

Single-episode limitation: After just one episode, the Q-values are unstable and far from optimal because the agent has only limited experience.

  • The agent has seen only one sequence of transitions and rewards.
  • It may not have discovered the path to the best goal yet.
  • It has no basis to distinguish between unlucky and genuinely bad actions.
  • Q-values reflect noise and the specific random choices made in that episode, not the true value.

Q-learning requires many episodes to converge. After one episode, the Q-table is unreliable. Convergence occurs when Q-values stabilize across episodes, meaning the agent has explored enough to learn a robust estimate of true value.

Multiple episodes and convergence

Convergence through repetition: With each additional episode, the agent explores different paths, updates Q-values, and gradually approaches the true optimal values.

  • Episode 1–N (exploration phase): Agent tries different actions and discoveries. Q-values shift significantly with each update.
  • Discovery: With enough episodes, the agent will find high-reward paths and update Q-values accordingly.
  • Stabilization: As more episodes occur, Q-values stop changing much because the estimates are already close to truth.
  • Convergence criterion: Learning is complete when Q-values stabilize (changes fall below a threshold) across episodes.
  • Learned policy: Once converged, the agent has learned the optimal policy: from any state, pick the action with the highest Q-value.

Convergence is not guaranteed in all settings (e.g., if the environment is non-stationary or the agent never explores crucial states). However, in well-behaved finite-state, finite-action environments with proper exploration, Q-learning is guaranteed to converge to the optimal Q-values.

Bias and Fairness in Machine Learning

Overview
  • What: Understanding how human biases encoded in data are amplified by machine learning models, and how to identify, measure, and mitigate unfair outcomes across population groups.
  • How it breaks down:
    • Why fairness matters — high-stakes impact and why ML is not neutral
    • The four types of bias — where bias enters the ML pipeline and what each looks like
    • Case studies of real systems — Amazon hiring, Optum healthcare, Gender Shades, COMPAS
    • Fairness metrics and trade-offs — why no single definition of fairness works for all cases
    • Intervention strategies — pre-processing, in-processing, and post-processing techniques to reduce bias
    • Deployment checklist — questions to ask before and after release
  • Takeaway: Fairness is not a one-time fix to the model; bias enters at every stage of the data pipeline, and no algorithm can simultaneously satisfy all fairness metrics when base rates differ. Mitigation requires auditing, choosing a metric aligned with values, intervening at the right stage, and monitoring continuously.

Why fairness matters

ML is not neutral

ML amplifies human bias: Models trained on human-generated data automatically inherit and automate the biases embedded in past decisions.

  • Human decisions are shaped by societal prejudices, historical inequities, and incomplete information.
  • When this biased data is used to train ML models, the model learns to replicate and often amplify those patterns.
  • The result appears objective (it is "just math") but systematically disadvantages certain groups.

Think of the pipeline as a photocopier: if you photocopy a biased document and then use that copy as the original for the next copy, the bias gets clearer with each iteration. A model trained on biased historical decisions is like the second and third photocopy—the unfairness is both preserved and sharpened.

High-stakes applications

Fairness is critical where decisions affect lives and opportunities.

Domain Consequence of Bias
Employment Qualified candidates filtered out based on protected attributes (gender, race); job market access denied.
Healthcare Patients systematically under- or over-triaged; certain groups denied care or resources they need.
Criminal justice Risk scores influence bail, sentencing, and parole; biased predictions lock certain groups in cycles of incarceration.

In high-stakes domains, algorithmic bias is not just a technical problem—it is a civil rights and public health issue. It can perpetuate and scale discrimination at a speed and scale humans never could.

Definition of algorithmic bias

Algorithmic bias: Systematic, unfair discrimination in model outputs that creates different outcomes for different groups, where group membership should not matter.

  • Key distinction: Not all differences in model output across groups are bias. Bias = (difference) + (unjustified) + (harmful).
  • Unjustified: The difference does not follow from valid differences in the underlying task (e.g., if a job requires physical strength, a height difference in hiring may be justified; a gender difference is not).
  • Harmful: The difference disadvantages one group relative to another.

A model may show different accuracy across groups without being biased in the fairness sense. Example: a model that classifies diseases based on visual symptoms may have different accuracy on people with different skin tones if the training data was imbalanced—this is a bias problem (representation bias, specifically). But a model that performs better on taller people for a height-prediction task may not be a fairness issue (the difference is justified by the task).

The four types of bias

Historical bias

Historical bias: Past social inequalities and unfair patterns in the world are reflected in historical data, and the model learns to replicate them.

  • Source: The data itself contains real-world injustice from the past.
  • Example: A loan approval model trained on historical lending decisions learns that applicants from historically redlined zip codes have higher default rates. But that higher rate was caused by systematic denial of credit, not lack of creditworthiness. The model perpetuates this injustice.
  • Challenge: The bias is not in the model logic; it is in the ground truth that the model is trying to learn from.

Historical bias is often the hardest to fix because the training labels themselves (which were supposed to be ground truth) encode historical unfairness. Simply training accurately on biased data produces a fair-seeming but unfair model.

Representation bias

Representation bias: The training data does not reflect the diversity of the real-world population, so the model learns patterns from only a subset and fails on underrepresented groups.

  • Source: Imbalanced or non-representative data collection.
  • Example: A medical image classification model trained primarily on images of fair-skinned patients learns features optimized for that skin tone and performs poorly on darker skin tones.
  • Mechanism: The model is not explicitly penalizing underrepresented groups; it simply has not learned their patterns because they are rare in training.
Measurement bias

Measurement bias: The features or labels used in the model are systematically different across groups, causing the model to learn spurious or unfair correlations.

  • Source: A proxy variable that does not mean the same thing for all groups.
  • Example: Using past healthcare costs as a proxy for "health need." In a population with unequal access to care, this proxy is corrupted: lower access → lower costs → model thinks group needs less care (even if medical need is high).
  • The proxy problem: The label itself is biased; the model accurately learns the biased label, producing unfair predictions.

Measurement bias often hides in the labels. Before training, ask: "Does this label mean the same thing for every group?" If the answer is no, you have a measurement bias problem that no amount of model tuning can fix—you must change the label.

Aggregation bias

Aggregation bias: Forcing a single model to serve groups with different base rates or characteristics, even when a stratified approach (separate models per group) would be more accurate and fair.

  • Source: Over-simplification; treating a heterogeneous population as homogeneous.
  • Example: A single recidivism model applied to two neighborhoods with different crime rates and policing intensity. The "one-size-fits-all" model may appear accurate in aggregate but be systematically wrong for both neighborhoods when used in isolation.
  • Trade-off: Building separate models increases complexity but may reduce unfairness if groups have genuinely different base rates.

Question Bias Type
Is past unfairness in my training data? Historical
Does my data look like the real world? Representation
Are my labels valid across groups? Measurement
Should I split into multiple models? Aggregation

Case studies of real systems

Case Study 1: Amazon Hiring (Historical Bias)

Problem: Amazon's automated resume screening system learned to discriminate against women by replicating historical hiring patterns.

Timeline and Discovery

  • 2014: Amazon begins building a machine-learning tool to automatically screen resumes at scale (millions per year).
  • 2015: Internal team discovers the model is systematically downrating resumes from women.
  • 2017: Amazon discontinues the tool.

The mechanism

  • Training data: Historical resumes and hiring decisions. Most people already hired in tech were men.
  • What the model learned: "Male-associated patterns → higher hire rate." Not because men were inherently better, but because hiring historically favored men.
  • Biased decisions:
    • Penalized resumes with the word "women."
    • Downgraded graduates from all-women's colleges.
    • Assigned lower scores to female-associated activities (e.g., women's chess club vs. men's chess club).

Why it happened

The model did not learn discrimination because engineers programmed it to. It learned discrimination because the training data encoded it: the ground truth showed men were hired more often, and the model replicated that pattern.

Why fixing it was hard

  • Engineers tried to remove gender-related words from the input.
  • Bias kept reappearing through hidden correlations (e.g., gender-associated college names, gender-associated activities).
  • Eventually, Amazon abandoned the approach rather than chase every proxy.

Removing gender as a feature is not enough when gender correlates with many other features in the training data. Bias hides in indirect proxies and is hard to eliminate by feature selection alone.

Case Study 2: Optum Healthcare (Measurement Bias)

Problem: Optum's patient risk-stratification algorithm used healthcare costs as a proxy for health need, but this proxy meant something different for different racial groups.

The system

  • Goal: Identify high-risk patients who need extra care management (nurses, check-ins, proactive interventions).
  • Approach: Predict future healthcare costs. High predicted cost = high risk = send extra resources.
  • Justification: Sicker patients should cost more and need more resources.

The bias

White patientsBlack patients
Less likely to be identified Identified as high- risk Same illness severity Received less Received more Extra care resourcesLess likely to be identified Identified as high- risk Same illness severity Received less Received more Extra care resources

At the same level of illness severity, Black patients were half as likely to be flagged for extra care. Why?

  • Root cause: Black patients historically had lower access to healthcare.
  • Result: Their past healthcare costs were lower (they received fewer services, not because they were healthier, but because they had less access).
  • Model learned: "Low costs → low need," even when the low costs resulted from barriers to access, not actual low need.

The fix

  • Instead of historical costs, use a label less correlated with access: "number of chronic conditions."
  • Adjust for access barriers explicitly in the model.
  • Result: More accurate and fairer identification of high-need patients across groups.

Measurement bias often hides in the choice of label. The label appeared to measure "health need" but actually measured "historical healthcare access." Always ask: does this label mean the same thing for every demographic group?

Case Study 3: Gender Shades (Representation Bias)

Problem: Commercial facial recognition systems (IBM, Microsoft, Face++) were trained on datasets that were 80–86% light-skinned faces, causing massive accuracy gaps for darker-skinned people, especially women.

The discovery

  • 2015: MIT graduate student Joy Buolamwini encountered a face-tracking system that could not detect her face but worked perfectly for her light-skinned classmates.
  • Hypothesis: The system was trained on unrepresentative data dominated by light-skinned faces.

The experiment (2018, published in PNAS as "Gender Shades")

  • Created a balanced dataset of 1,270 faces from 3 African countries and 3 European countries.
  • Balanced by gender and skin tone.
  • Tested three commercial gender classification systems: IBM Watson, Microsoft, and Face++.

The results

20.4% 79.6% IJB-A 13.8% 86.2% Adience20.4% 79.6% IJB-A 13.8% 86.2% Adience

Lighter-skinned males 0.3% (best)
Lighter-skinned females ~7%

Darker-skinned females 34.7% (worst)
  • Intersectional gap: Darker-skinned females were misgendered at rates 100× higher than lighter-skinned males.
  • By company:
    • Microsoft: 93% of mislabeled faces were darker-skinned subjects.
    • Face++: 95% of mislabeled faces were female subjects.

    • Face++: 30.4% error reduction (biggest improvement).

Gender Shades shows that representation bias can be measured and improved. The key is collecting balanced evaluation data and testing performance on underrepresented groups before deployment. Academic scrutiny and public disclosure accelerated industry fix.

Case Study 4: COMPAS (Fairness Trade-offs)

Problem: COMPAS, a recidivism prediction tool used in US courts, showed different error rates across racial groups—but which fairness metric to use was controversial and unresolvable.

The system

  • Developer: Northpointe.
  • Use: Over 1 million cases in dozens of US states.
  • Task: Predict whether a defendant will re-offend (commit another crime) within 2 years.
  • Impact: Risk scores (1–10) influence bail amounts, sentencing decisions, and parole eligibility.

The investigation (ProPublica, 2016)

  • Obtained COMPAS scores for 7,000+ defendants in Broward County, Florida (2013–2014).
  • Tracked actual re-offense within 2 years.
  • Compared performance across racial groups (White and Black defendants).

The findings

White defendantsBlack defendants
56% 46% % labeled "high risk" 52% 35% % who actually re- offended56% 46% % labeled "high risk" 52% 35% % who actually re- offended

Both groups showed similar overall accuracy (~60% labeled high-risk, ~50% actually re-offended). But the errors were distributed differently:

White defendantsBlack defendants
45% 28% False Positive Rate45% 28% False Positive Rate
White defendantsBlack defendants
28% 48% False Negative Rate28% 48% False Negative Rate
  • False Positive Rate (labeled high-risk but did NOT re-offend): 45% for White defendants, 28% for Black defendants. → Black defendants were more likely to be correctly identified as low-risk.
  • False Negative Rate (labeled low-risk but DID re-offend): 28% for White defendants, 48% for Black defendants. → Black defendants labeled low-risk were more likely to actually re-offend.

The conflict

  • ProPublica's claim: COMPAS is racially biased (higher false positive rate for Black defendants).
  • Northpointe's defense: COMPAS is equally accurate across groups (same risk score means same likelihood of re-offense, regardless of race—this is "calibration").
Fairness Metric Definition COMPAS Performance
Equalized odds False positive rates equal across groups Fails (45% vs 28%)
Calibration Same score → same likelihood of outcome, regardless of race Passes

The deeper problem

Both metrics cannot be satisfied simultaneously when base rates differ. In this case:

  • Base rate for White defendants: ~35% re-offend.
  • Base rate for Black defendants: ~52% re-offend.

Mathematical impossibility: When two groups have different base rates (proportions with the outcome), no classifier can simultaneously have equal false positive rates AND equal false negative rates across groups. Choosing equalized odds means accepting unequal false negative rates; choosing calibration means accepting unequal false positive rates.

The takeaway

COMPAS illustrates that fairness is not a property of the algorithm alone—it is a choice about whose errors you prioritize.

No single definition of fairness works for all cases. Equalized odds protects against false accusations; calibration protects against misjudgment of risk for those who are flagged. Choosing between them is a values decision, not a technical one.

Fairness metrics and mathematical trade-offs

Definition of fairness: no single answer

Fairness in ML: There is no single universally accepted definition. Different stakeholders prioritize different error types and outcomes.

  • Equalized odds: False positive and false negative rates are equal across groups. Protects against false accusations but can mask different error burdens.
  • Calibration: A given risk score means the same probability of outcome for all groups. Ensures consistency but can allow unequal false positive rates.
  • Demographic parity: The proportion predicted positive is the same across groups. Ignores accuracy but ensures resource allocation is balanced.
  • Individual fairness: Similar individuals receive similar decisions. Hard to define "similar" and check in practice.

Choosing a fairness metric is not a technical question; it is a values and policy question. It reflects what kind of errors society finds more acceptable and whom the system is primarily accountable to.

Why metrics conflict when base rates differ

Base rate: The proportion of the population for which the outcome is true (e.g., re-offending, loan default, disease presence).

Mathematical impossibility (when base rates differ): It is impossible to simultaneously have equal false positive rates AND equal false negative rates across two groups if the base rates are different. At least one group will experience higher error on one error type.

  • If group A has a higher base rate (more individuals with the outcome), a classifier that achieves equal false positive rates will necessarily have unequal false negative rates.
  • This is not a failure of the algorithm; it is a mathematical constraint.
  • Choosing equalized odds means accepting unequal false negatives; choosing to minimize false negatives means accepting unequal false positives.

Intervention strategies and mitigation

The bias pipeline: where intervention is possible

Bias pipeline: Bias enters before the model; it is baked into the data and labels. Intervention can occur at three stages.

Three places to intervene on bias, in order of difficulty and impact:

Stage Name Difficulty Example
Before training Pre-processing (fix data) Medium Reweight samples; collect more data from underrepresented groups; audit training data for missing voices.
During training In-processing (fix model) Hard Add fairness constraints to the objective; penalize unequal error rates during optimization.
After training Post-processing (fix outputs) Easy Adjust decision thresholds per group; calibrate scores; modify predictions after model evaluation.
Pre-processing: reweighting

Reweighting: Assigning higher weight to underrepresented or historically disadvantaged groups during training, so the model "cares more" about getting those examples correct.

  • Mechanism: During training, the loss for a sample from an underrepresented group contributes more to the total loss, pulling the model toward better performance on that group.
  • Example (Amazon hiring): Give female resumes 2× the weight during training. The model will optimize to minimize errors on female examples, counteracting the historical bias.
  • Advantage: Simple to implement; does not require changing the model architecture.
  • Limitation: Does not fix the underlying data if the label itself is biased (measurement bias).
Post-processing: threshold adjustment

Threshold adjustment: After training, use different decision thresholds for different groups to achieve fairness metrics.

  • Mechanism: A classifier outputs a probability or score. The decision threshold (e.g., "if score > 0.5, classify positive") can be different per group.
  • Example: To equalize false positive rates, lower the threshold for the group that currently has a high false positive rate, so more members are classified as negative.
  • Advantage: Does not require retraining; can be applied after any model.
  • Limitation: Can reduce overall accuracy; thresholds must be chosen carefully to balance fairness and performance.
