*** THE FOOTER IS THE IMPORTANT PART ***
  "Changes apply to all views showing this property."

  Notion explicitly tells the user the SCOPE of what they are editing —
  data-source-level (schema), not view-level. That matters because the same panel
  stack also hosts view-level settings, and the two are visually identical.

  This is directly relevant to us: our backend has the same split
  (db_properties belongs to a data source; view.config belongs to a view), and
  the UI currently makes no distinction at all. ADOPT THIS PATTERN — any panel
  editing schema-level state carries a scope disclaimer in its footer.

  MenuPanel.footer now has THREE established uses:
    1. metadata      ("Last edited by …", row menu)
    2. scope         ("Only applies to you", Display as)
    3. scope         ("Changes apply to all views…", Edit property)
  Uses 2 and 3 are opposite scopes — per-user vs all-views. The footer is where
  Notion disambiguates them.

ROW ANATOMY
  - "Number format" and "Decimal places" are value+chevron rows (sub-panels).
  - "Show as" is a SECTION containing a CARD GRID (icon/preview above label),
    the same card idiom as the view-type grids but at 3 columns and with a live
    preview rather than an icon ("42" rendered, a bar, a ring).
  → The card-grid element is reused across unrelated surfaces (view types,
    number display). Build it once as a primitive, parameterised by column count.
