*** ARCHITECTURAL FINDING — ONE SHARED SIDEBAR, MANY PANELS ***
  container class : notion-view-settings-sidebar
  geometry        : x=898, y=166, width=483, height=427

  This is the SAME container and the SAME 483px width as the view settings panel
  (view-settings-sidebar.txt). Notion does not open a bespoke popover per
  configuration surface — it reuses ONE right-hand sidebar and swaps its contents.

  Consequences for our design:
  - `SidePeek` is not just for row peeks. It is the host for view settings,
    property configuration, relation configuration — probably more.
  - The design doc's split (Popover+MenuList for menus, SidePeek for row peek) is
    too clean. There is a third thing: a docked CONFIG SIDEBAR with a panel stack.
    It needs its own primitive, or SidePeek needs a panel-stack mode.
  - Width 483px is a token, not a per-surface decision.
