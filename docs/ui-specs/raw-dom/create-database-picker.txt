*** THIS IS THE MOST IMPORTANT CAPTURE SO FAR ***
Creating a database in Notion does NOT go straight to an empty table. It opens a
full-viewport modal that asks WHICH DATA SOURCE the new database should show.
That is the post-2025 database/data-source split — the exact model our backend
already implements (db_databases -> db_data_sources) and our UI exposes NOWHERE.
Our Sidebar.tsx `handleNewDatabase` POSTs {title:"Untitled Database"} and
navigates straight to the result.

  Vertical scroll, with a visible scrollbar track on the right.

KEYBOARD  (established with REAL key events — computer permission granted)
- **Escape does NOT dismiss this modal.** Pressed twice, with focus in the Search
  input both times; the modal stayed open and focus stayed in the input. Closing
  requires clicking the × at the top left.
  This is unusual and is exactly the assumption a memory-written spec would get
  backwards. Our own modals close on Escape; if we copy this surface we must decide
  deliberately whether to copy the non-dismissal too (recommendation: do NOT — it
  reads as a bug, and our ConfirmDialog/PromptDialog convention is Escape-closes).
- Focus on open: the Search input, verified via document.activeElement.
- Not yet established: arrow-key navigation across the card grid, Enter to pick.
