================= CELL INTERACTION IS TWO-STAGE =================
  1st click  → SELECTS the cell. A blue border appears, plus a small circle at
               the cell's bottom-right corner. NO editor opens.
  2nd click  → OPENS the editor in place.
  Enter on a selected cell did NOT open the editor in this test (pressed once
  after the first click, nothing happened) — TBD whether Enter opens editors for
  other types, or whether a second click is the only route.

  → This two-stage model is a real difference. Our cells (cells/SelectCell.tsx
    etc.) open their editor on the FIRST click. Notion's first click is a
    spreadsheet-style selection.
  → The corner circle is the same unexplained affordance noted in
    row-affordances-and-menu.txt. Still TBD; it appears on cell SELECTION.

================= THE SELECT EDITOR =================
Opens IN PLACE — the cell itself becomes a search input; a panel hangs below it.

STATE: no options exist yet
--- verbatim ---
[ Search for an option…  ]        ← the cell becomes this input, autofocused
Select an option or create one    ← EMPTY-STATE copy, muted
--- end ---

STATE: after typing "Alpha"
--- verbatim ---
[ Alpha ]
Select an option or create one
Create  [Alpha]                   ← "Alpha" rendered as a COLOURED CHIP PREVIEW
--- end ---

  *** The create row PREVIEWS the chip with its auto-assigned colour. ***
  You see what the option will look like before committing. Notion assigns the
  colour itself; the user does not pick it at creation time.
  Our RelationPicker/SelectCell have no create-on-type at all — a select option
  can only be added by editing the property.

STATE: after Enter
  The option is created, applied to the cell, and rendered as a chip in the cell.
  One keystroke does: create option + assign value + close editor.
