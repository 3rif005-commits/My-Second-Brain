What Reinforcement Learning Is

Reinforcement Learning (RL)

Reinforcement Learning: Learning what to do (which action to take) based on rewards and punishments received from the environment.

RL is the third major branch of machine learning, alongside supervised and unsupervised learning. Where supervised learning maps inputs to correct outputs with a teacher, and unsupervised learning finds hidden patterns, RL agents learn by taking actions and receiving feedback signals that guide them toward maximizing cumulative reward.

Think of RL like a pet learning tricks for treats: the pet tries an action, receives a reward (treat) or nothing, and gradually learns which behaviors earn rewards. There is no instruction manual—only trial, feedback, and adaptation.

The Five Core Components

Agent, Environment, Action, State, Reward
  • Agent: The learner—the entity that makes decisions and acts (e.g., a robot, game AI).
  • Environment: The world the agent interacts with—everything outside the agent that responds to its actions (e.g., a grid, a game board, a physical space).
  • Action: What the agent can do—a choice available to it in its current state (e.g., move up, down, left, right; play a chess move).
  • State: Where the agent is—a snapshot of the environment at a moment in time (e.g., the robot's current cell in a grid, the current board configuration).
  • Reward: Feedback signal from the environment—a number indicating how good or bad the outcome of an action was (e.g., +10 for reaching a goal, −1 for each step taken, −10 for hitting a penalty).

These five components form a loop: the agent observes its state, chooses an action, transitions to a new state, receives a reward, and repeats. RL algorithms learn to predict and maximize the total accumulated reward over many such loops.

The "No Teacher" Principle

Learning Without Instructions or Ground Truth

The "No Teacher" Principle: The agent has no correct path, no answer key, and no external instructor—only feedback signals (rewards and penalties) that it must learn to interpret.

In an RL scenario, an agent explores an unknown environment with no map or instructions. It receives only:

  • Intermediate feedback: "Warmer" (small positive reward) or "colder" (small negative reward) signals that guide direction.
  • Terminal feedback: Large positive rewards for reaching goals (e.g., candy) or large negative penalties for failure (e.g., lemon).

The agent improves by accumulating these rewards over time, learning which actions lead to better outcomes through experience rather than through explicit instruction. This is fundamentally different from supervised learning, where a teacher provides the correct answer for every input.

Why RL? When to Use It

Applications Where RL Is the Right Tool
Application Why RL?
Self-driving cars No "correct" steering label exists for every situation; the agent must learn to adapt to diverse, dynamic environments.
Game AI (AlphaGo, Chess) Opponents adapt and respond; there is no fixed answer key. Only feedback (win/loss/score) is available.
Robot navigation The environment is unknown or changing, so no pre-labeled training data exists.
Recommendation systems User feedback is sequential and depends on context; the system learns by trial and user response, not from one-shot labels.

Use RL when your problem involves an agent interacting with a dynamic or unknown environment and receiving delayed or sequential feedback. If you have a complete labeled dataset with correct answers, supervised learning is more direct.

The Exploration-Exploitation Dilemma

Exploitation vs. Exploration

The Exploration-Exploitation Dilemma: Should the agent do what it already knows works (exploit), or try something new that might be better (explore)?

  • Exploitation: Choosing the action with the highest known reward (the greedy choice, based on current Q-values). This maximizes immediate reward but may trap the agent in a local optimum.
  • Exploration: Choosing a random or less-certain action to discover new paths and potentially better rewards. This risks short-term losses but can reveal superior long-term strategies.

Exploiting only (always choosing the best known action) can cause the agent to miss undiscovered, better paths. Exploring only (always choosing randomly) prevents the agent from using what it has learned. Balancing the two is essential and is a core part of the Q-Learning algorithm's design.

Value-Based Reinforcement Learning

The Value-Based Framework

Value-based RL: An approach that learns a value function (which states or state-action pairs are good) and derives an optimal policy (which actions to take) from those values.

In value-based methods, the agent learns estimates of how good it is to be in a given state or to take a given action in a state. These estimates, called value functions, then determine the policy: the agent simply chooses the action with the highest estimated value.

Value function → Policy → Cumulative reward. The value function is the input; the policy is derived from it; the reward is the outcome. Q-Learning is the algorithm that learns these value functions.

Value Functions: State and State-Action

V(s) and Q(s, a)
  • State Value Function V(s): A number that represents how good it is to be in state s. It answers: "If I am in state s and act optimally from here on, what total reward will I accumulate?"
  • State-Action Value Function Q(s, a): A number that represents how good it is to take action a in state s. It answers: "If I take action a in state s and then act optimally, what total reward will I accumulate?"

Q-Learning focuses on learning Q(s, a) values, which are more directly useful: they explicitly tell the agent which action to take in each state (the one with the highest Q-value).

V(s) is like knowing a restaurant's overall quality; Q(s, a) is like knowing the quality of a specific dish at that restaurant. Q-values are more informative for decision-making because they tell you exactly which choice to make.

The Q-Value Table

Organizing Q-Values as a Matrix

Q-Value Table: A matrix indexed by states (rows) and actions (columns), where each cell Q(s, a) contains the learned value for taking action a in state s.

Q A1 A2 A3 A4
S1 Q(S1, A1) Q(S1, A2) Q(S1, A3) Q(S1, A4)
S2 Q(S2, A1) Q(S2, A2) Q(S2, A3) Q(S2, A4)
S3 Q(S3, A1) Q(S3, A2) Q(S3, A3) Q(S3, A4)
S4 Q(S4, A1) Q(S4, A2) Q(S4, A3) Q(S4, A4)

The agent updates entries in this table as it learns. To choose an action in state s, it looks at row s and picks the column (action) with the highest value.

The Goal of Q-Learning

Learning Optimal Q-Values

Goal of Q-Learning: Learn Q-values that accurately estimate the total discounted future reward for each state-action pair, so that the agent can make decisions that maximize cumulative reward.

Q-Learning is an algorithm that iteratively refines Q-value estimates through experience. Initially, Q-values are arbitrary (often initialized to 0). Each time the agent takes an action, receives a reward, and observes the resulting state, it updates the Q-value for that state-action pair to move it closer to the truth. Over many episodes, these estimates converge to the true optimal Q-values, and the agent learns the best policy.

Q-Learning in Practice

The Agent's Decision Process
  1. The agent starts in state S1 (or a random starting state).
  2. It chooses an action using an exploration policy (not by looking at Q-values).
  3. The action is chosen by random chance—this random decision-making strategy is called the behavior policy.
  4. The agent transitions to a new state and receives a reward.
  5. The Q-value for the state-action pair is updated based on the observed outcome.

The behavior policy is random (or ε-greedy, which is mostly random but occasionally chooses the best-known action). This ensures exploration. The optimal policy is later extracted from the learned Q-values, by always choosing the action with the highest Q-value in each state.

The Bellman Equation and Discount Factor γ

Computing the Observed Q-Value

Bellman Equation for Q-values: The observed (true) Q-value for taking action a in state s is the immediate reward plus the discounted max Q-value in the next state.

Bellman Update for Q-Learning

Q(s, a)_{\text{observed}} = R(s') + \gamma \max_{a'} Q(s', a')
  • Q(s, a)_observed: The true Q-value we are trying to estimate for taking action a in state s.
  • R(s'): The immediate reward received upon transitioning to state s'.
  • γ (gamma): The discount factor, a value between 0 and 1 that weights future rewards relative to immediate rewards.
  • maxa' Q(s', a'): The highest Q-value for any action in the next state s'—representing the best the agent can do from there.

The Bellman equation says: the value of a state-action pair is the immediate reward you get, plus a discounted estimate of how good the resulting state is. This recursive structure links each Q-value to the values of its successors.

Understanding the Discount Factor γ

Discount Factor γ: A value between 0 and 1 that represents how much the agent cares about future rewards compared to immediate rewards.

  • γ = 0: Robot only cares about the immediate reward; future rewards have no weight. The agent is myopic.
  • γ = 0.5: Future rewards matter half as much as immediate rewards.
  • γ = 0.9: Future rewards matter, but slightly discounted relative to today's reward. A common, practical choice.
  • γ = 1: Robot values future rewards equally to immediate rewards. The agent treats all rewards in time equally.

In practice, γ is usually between 0.9 and 0.99. A value close to 1 makes the agent plan far ahead; a value closer to 0.5 makes it focus on nearby rewards. The choice depends on the problem's horizon and the importance of long-term planning.

Temporal Difference Error

TDE: Measuring the Q-Value Gap

Temporal Difference Error (TDE): The difference between the observed (true) Q-value and the current expected (stored) Q-value, measuring how wrong the current estimate is.

Temporal Difference Error

\text{TDE} = Q(s, a)_{\text{observed}} - Q(s, a)_{\text{expected}}
  • Q(s, a)_observed: The true Q-value computed from the Bellman equation using the reward just received and the next state.
  • Q(s, a)_expected: The Q-value currently stored in the table (what the agent believes before this update).

The TDE tells you the direction and magnitude of the correction needed: a positive TDE means the stored Q-value was too low (the action was better than expected), and a negative TDE means it was too high (the action was worse than expected).

Interpreting TDE
  • TDE > 0: The observed Q-value is higher than expected. The action was better than the agent thought. Increase the Q-value.
  • TDE = 0: The observed and expected Q-values match. The estimate is accurate; no update is needed.
  • TDE < 0: The observed Q-value is lower than expected. The action was worse than the agent thought. Decrease the Q-value.

The Update Rule and Learning Rate α

Adjusting Q-Values Incrementally

Q-Learning Update Rule: Update the Q-value by moving it a fraction of the way toward the observed Q-value, scaled by the learning rate α.

Q-Value Update Rule

Q(s, a)_{\text{new}} = Q(s, a)_{\text{old}} + \alpha \times \text{TDE}
  • Q(s, a)_old: The stored Q-value before this update.
  • α (alpha): The learning rate or step size, a value between 0 and 1.
  • TDE: The temporal difference error computed above.

This rule moves the stored Q-value toward the observed value in small increments. The learning rate α controls how much to trust each new observation: a large α means big jumps (fast but noisy learning), a small α means tiny steps (slow but stable learning).

Understanding the Learning Rate α

Learning Rate α: How much weight to give each new observation when updating a Q-value, measured as a fraction between 0 and 1.

  • α = 1.0: Fully trust the observed Q-value; replace the old estimate entirely. Can cause instability if the observation is a fluke.
  • α = 0.5: Average the old and observed values equally. A moderate, balanced update.
  • α = 0.1: Trust the old estimate much more. Changes are small, but many updates are needed for convergence. Stable against noise.
  • α = 0.01: Very small updates. Very stable but slow to learn.

In practice, α is often 0.1 or 0.01 for stability. If learning is too slow, slightly increase α; if Q-values oscillate wildly, decrease it.

Worked Example: S1 → S4 (Down)

First Step Update

The agent is in state S1 and takes action down, transitioning to S4.

Given:

  • S1, action: down → S4
  • Reward R(S4) = −1
  • Current Q(S1, down) = 0.75
  • Q-values in S4: Left 0.5, Right 0.75, Up −0.5, Down 1.5
  • γ = 0.1, α = 0.1

Step 1: Compute Observed Q-value (Bellman equation)

Q(S1, \text{down})_{\text{observed}} = R(S4) + \gamma \max_a Q(S4, a) = -1 + 0.1 \times 1.5 = -0.85

Step 2: Compute Temporal Difference Error

\text{TDE} = Q(S1, \text{down})_{\text{observed}} - Q(S1, \text{down})_{\text{expected}} = -0.85 - 0.75 = -1.6

Step 3: Update Q-value

Q(S1, \text{down})_{\text{new}} = Q(S1, \text{down})_{\text{old}} + \alpha \times \text{TDE} = 0.75 + 0.1 \times (-1.6) = 0.59

Result: Q(S1, down) is updated from 0.75 to 0.59. The agent discovered that this action leads to a worse outcome than expected (negative TDE), so it lowered the Q-value.

Worked Example: S4 → S5 (Right)

Second Step Update

The agent continues from S4 and takes action right, transitioning to S5.

Given:

  • S4, action: right → S5
  • Reward R(S5) = −2
  • Current Q(S4, right) = 0.75
  • Q-values in S5: Left −1.2, Right 1.2, Up 0.7, Down 1.7
  • γ = 0.1, α = 0.1

Step 1: Compute Observed Q-value

Q(S4, \text{right})_{\text{observed}} = R(S5) + \gamma \max_a Q(S5, a) = -2 + 0.1 \times 1.7 = -1.83

Step 2: Compute Temporal Difference Error

\text{TDE} = -1.83 - 0.75 = -2.58

Step 3: Update Q-value

Q(S4, \text{right})_{\text{new}} = 0.75 + 0.1 \times (-2.58) = 0.49

Result: Q(S4, right) is updated from 0.75 to 0.49. Again, the observed outcome was worse than expected.

Worked Example: S5 → S6 (Right) with γ = 0.1

Third Step: Standard Discount

The agent moves from S5 to S6 by going right.

Given:

  • S5, action: right → S6
  • Reward R(S6) = −1
  • Current Q(S5, right) = 1.2
  • Q-values in S6: Left 0.8, Right 1.4, Up 2.0, Down 0.5
  • γ = 0.1, α = 0.1

Step 1: Compute Observed Q-value

Q(S5, \text{right})_{\text{observed}} = R(S6) + \gamma \max_a Q(S6, a) = -1 + 0.1 \times 2.0 = -0.8

Step 2: Compute Temporal Difference Error

\text{TDE} = -0.8 - 1.2 = -2.0

Step 3: Update Q-value

Q(S5, \text{right})_{\text{new}} = 1.2 + 0.1 \times (-2.0) = 1.0

Result: Q(S5, right) decreases from 1.2 to 1.0.

Worked Example: S5 → S6 (Right) with γ = 0.9

Same Transition, Higher Discount Factor

Now suppose γ = 0.9 instead. Same transition S5 → S6 right, reward −1.

Step 1: Compute Observed Q-value

Q(S5, \text{right})_{\text{observed}} = R(S6) + \gamma \max_a Q(S6, a) = -1 + 0.9 \times 2.0 = 0.8

Step 2: Compute Temporal Difference Error

\text{TDE} = 0.8 - 1.2 = -0.4

Step 3: Update Q-value

Q(S5, \text{right})_{\text{new}} = 1.2 + 0.1 \times (-0.4) = 1.16

Comparison:

γ Observed Q-value TDE New Q-value
0.1 −0.8 −2.0 1.0 (big decrease)
0.9 0.8 −0.4 1.16 (small decrease)

A higher γ makes the robot more tolerant of short-term negative rewards when future rewards are promising. With γ = 0.9, the agent "sees through" the immediate −1 penalty and recognizes that the next state (S6) has good options (max Q = 2.0). With γ = 0.1, future rewards are heavily discounted, so only the immediate penalty matters.

Episodes and Convergence

What Is an Episode?

Episode: One complete run from a starting state to a terminal state (goal reached or failure/penalty).

In the grid example:

  • Episode starts: The robot begins at S1 (or a randomly chosen starting state).
  • Episode ends: The robot reaches S9 (goal, reward +10) or S8 (penalty, reward −10), or after a maximum number of steps.
  • A partial episode: The sequence S1 → S4 → S5 → S6 → ... is a partial episode in progress; it has not yet reached a terminal state.

Why Multiple Episodes Are Needed

Convergence Through Repeated Exploration

One Episode Is Insufficient: After a single episode, the robot's Q-values are still incorrect or unstable because it has only experienced one path and has not discovered the true consequences of all actions.

Consider the worked example path S1 → S4 → S5 → S6. At the end, Q(S1, down) = 0.59. But is this the true value? No, because:

  • The robot has not yet discovered the path to S9 (the goal with reward +10).
  • It has only experienced negative or neutral rewards so far (−1, −2, −1).
  • It has not tested other actions that might lead to better outcomes.

Why Multiple Episodes Work:

  1. Each episode gives the robot new experience. In episode 2, it may explore different actions (due to random behavior policy).
  2. It may discover better paths and experience the +10 reward at S9.
  3. Each time a Q-value is updated, it becomes more accurate, and the improvement propagates to other states (via the Bellman equation).
  4. Over many episodes, Q-values converge: they stop changing significantly, because the observed and expected values align.

Convergence Criterion: When Q-values stop changing much across episodes, the agent has learned the optimal policy. At convergence, for each state, the agent knows exactly which action leads to the highest total discounted reward.

Learning Convergence and Termination

When Does Learning End?

After many episodes, the Q-value stops changing much. That is when learning is done. When Q-values stop changing, the robot has learned the optimal policy: from any state, it knows exactly which action leads to the highest total reward.

Signs of Convergence:

  • Updates to Q-values become very small (TDE approaches 0).
  • The agent's behavior stabilizes: it makes the same action choices in the same states.
  • The average cumulative reward per episode plateaus and stops improving.

Convergence is not instant. The number of episodes needed depends on the environment size, the learning rate α, and the discount factor γ. Large or complex environments may need thousands of episodes. Practitioners often run until a time budget is exhausted or a performance threshold is met, rather than waiting for true mathematical convergence.
