Core Components and the No Teacher Principle

Definition of Reinforcement Learning

Reinforcement Learning (RL): Learning what to do (which action to take) based on rewards and punishments received from the environment, with no instruction or correct path given.

The agent improves by accumulating rewards over time, discovering the mapping between actions and outcomes through trial and error.

The Five Core Components
  • Agent: The learner (e.g., a robot)
  • Environment: The world the agent interacts with (e.g., a grid)
  • Action: What the agent can do (e.g., move up/down/left/right)
  • State: Where the agent is at a given moment (e.g., a specific cell)
  • Reward: Feedback signal—positive for good outcomes, negative for bad, zero for neutral
The No Teacher Principle

No Teacher: The agent receives no instructions, no map, and no correct path—only feedback signals that guide learning.

Learning Process:

  • Agent takes actions (moves) in the environment
  • Agent receives rewards or penalties as feedback
  • Agent gradually learns which actions lead to better outcomes
  • Improvement happens by accumulating rewards over many interactions

When to Use Reinforcement Learning

Applications of Reinforcement Learning

RL is necessary: When the problem involves sequential decision-making where a correct label or policy does not exist upfront, and feedback is received after actions rather than before.

Application Why RL?
Self-driving cars No "correct" steering label for every situation; decisions depend on unknown environments and real-time conditions
Game AI (AlphaGo, Chess) Opponent adapts; no fixed answer key exists because the best move depends on the opponent's changing strategy
Robot navigation Environment is unknown or changing; the agent must learn by exploration, not from pre-labeled paths
Recommendation systems User feedback is sequential and delayed; good recommendations depend on learning from user interactions over time

Exploration vs. Exploitation

The Exploration-Exploitation Dilemma

Exploration-Exploitation Tradeoff: Should the agent do what it already knows works (exploit known good actions), or try something new that might be better (explore unknown actions)?

  • Exploitation: Greedy choice—select the action with the highest known Q-value (best expected reward so far)
  • Exploration: Random choice—try an action without looking at Q-values, to discover potentially better paths

A balanced strategy explores early (when the agent knows little) and gradually shifts to exploitation (as Q-values become more reliable). This prevents the agent from getting stuck in local optima.

Value-Based Methods and Q-Learning

Q-Learning

Q-Learning: A value-based reinforcement learning algorithm that learns the expected total reward for taking each action in each state, storing these estimates in a Q-table.

How Q-Learning Works:

  • The value function (Q-values) determines which action the agent should take
  • The policy is derived by selecting actions with the highest Q-values
  • Total reward is maximized when the agent follows a policy learned from accurate Q-values

State Value and State-Action Value Functions

State Value Function V(s)

V(s): A scalar value representing how good it is to be in state s, assuming the agent will act optimally from that state forward.

Useful for evaluating overall state quality, but does not specify which action to take.

State-Action Value Function Q(s,a)

Q(s,a): A scalar value representing how good it is to take a specific action a in a given state s, assuming the agent will act optimally thereafter.

More useful than V(s) because it directly tells the agent which action to choose: pick the action with the highest Q-value in the current state.

Q-Table Structure

Q-Table: A matrix indexed by states and actions, where each cell Q(s,a) stores the learned estimate of expected return for that state-action pair.

State Action 1 Action 2 Action 3 Action 4
S1 Q(S1,A1) Q(S1,A2) Q(S1,A3) Q(S1,A4)
S2 Q(S2,A1) Q(S2,A2) Q(S2,A3) Q(S2,A4)
S3 Q(S3,A1) Q(S3,A2) Q(S3,A3) Q(S3,A4)
S4 Q(S4,A1) Q(S4,A2) Q(S4,A3) Q(S4,A4)

Behavior Policy and Action Selection

Behavior Policy During Learning

Behavior Policy: The decision-making strategy the agent uses while learning, which determines how it chooses actions during exploration.

Learning Phase:

  • The agent starts in an initial state
  • It takes an action based on an exploration policy
  • The action is chosen by random chance, not by looking at Q-values
  • This random decision-making is the behavior policy during learning

Once learning is complete, the agent switches to a greedy policy: select the action with the highest Q-value in each state. This is the exploitation phase.

Q-Table Initialization

Initialization: At the start of learning, Q-values can be set to arbitrary values (often 0s) or small random numbers.

Even if the agent starts with zeros or random Q-values, the learning algorithm will correct them toward the true values over time through repeated updates.

The Bellman Equation

Bellman Equation for Q-Values

Bellman Equation: The recursive formula expressing the observed Q-value as the sum of the immediate reward and the discounted maximum Q-value in the next state.

For computing the observed Q-value of a state-action pair:

Q(s, a)_{\text{observed}} = R(s') + \gamma \max_{a'} Q(s', a')
  • Q(s,a)_observed: The observed (computed) Q-value when taking action a in state s
  • R(s'): The reward received upon arriving in the next state s'
  • γ (gamma): Discount factor; how much to weight future rewards (0 ≤ γ ≤ 1)
  • max_a' Q(s',a'): The maximum Q-value available in the next state (best future action)
Worked Example: Computing Observed Q-value from S1 to S4

Scenario: Agent is in state S1, takes action "down" to arrive at S4, and receives reward R(S4) = −1. The Q-table already contains Q-values for S4.

Action Q(S4, action)
Left 0.5
Right 0.75
Up −0.5
Down 1.5
  1. Identify the immediate reward: R(S4) = −1
  2. Find the maximum Q-value in the next state: max_a Q(S4, a) = max(0.5, 0.75, −0.5, 1.5) = 1.5 (Down action)
  3. Apply the Bellman equation with γ = 0.1:
    Q(S1, \text{down})_{\text{observed}} = -1 + 0.1 \times 1.5 = -1 + 0.15 = -0.85
  4. The observed Q-value is −0.85

Temporal Difference Error

Temporal Difference Error (TDE)

Temporal Difference Error: The difference between the observed Q-value (computed from the Bellman equation) and the expected Q-value (stored in the Q-table), which quantifies how wrong the current estimate is.

Computing the temporal difference error:

TDE = Q(s, a)_{\text{observed}} - Q(s, a)_{\text{expected}}
  • TDE: The error signal that drives learning
  • Q(s,a)_observed: The newly computed Q-value from the Bellman equation
  • Q(s,a)_expected: The old Q-value currently stored in the table

Interpretation:

  • TDE > 0: The observed value is higher than expected; the Q-value was underestimated
  • TDE < 0: The observed value is lower than expected; the Q-value was overestimated
  • TDE = 0: The stored Q-value was correct; no update needed
Worked Example: Computing TDE from S1 to S4

Scenario: Agent transitions from S1 (action down) to S4. The observed Q-value is −0.85 (computed above). The Q-table currently stores Q(S1, down) = 0.75.

TDE = -0.85 - 0.75 = -1.6

The temporal difference error is −1.6, indicating the stored Q-value (0.75) was significantly overestimated; the true value is 1.6 units lower.

The Q-Value Update Rule

Q-Value Update Rule

Update Rule: The Q-value is adjusted by adding the learning rate times the temporal difference error to the stored Q-value, moving the estimate incrementally toward the observed value.

Updating a Q-value based on the temporal difference error:

Q(s, a)_{\text{new}} = Q(s, a)_{\text{expected}} + \alpha \times TDE
  • Q(s,a)_new: The updated Q-value stored in the table
  • Q(s,a)_expected: The old Q-value before update
  • α (alpha): Learning rate; controls the step size of each update (0 < α ≤ 1)
  • TDE: Temporal difference error (observed − expected)

Learning Rate α:

  • α = 1.0: Fully replace the old Q-value with the observed value (aggressive)
  • α = 0.5: Move halfway toward the observed value
  • α = 0.1: Small incremental step (conservative, smoother learning)
  • α = 0: No update; learning stops
Worked Example: Updating Q(S1, down) with α = 0.1

Scenario: Stored Q(S1, down) = 0.75, observed Q-value = −0.85, TDE = −1.6, learning rate α = 0.1.

Q(S1, \text{down})_{\text{new}} = 0.75 + 0.1 \times (-1.6) = 0.75 - 0.16 = 0.59

The Q-value decreases from 0.75 to 0.59, moving toward the observed estimate (−0.85) by a small fraction controlled by α = 0.1. The table is updated to reflect the new estimate.

The Discount Factor γ

Discount Factor (Gamma)

Discount Factor γ: A parameter (0 ≤ γ ≤ 1) that scales future rewards in the Bellman equation, determining how much the agent values future reward compared to immediate reward.

γ Value Agent Behavior
γ = 0 Robot only cares about immediate reward; future rewards are ignored
γ = 0.5 Future rewards matter half as much as immediate rewards
γ = 0.9 Future rewards matter, but slightly less than immediate rewards
γ = 1.0 Robot values future rewards equally to immediate rewards; no discounting
Worked Example: Effect of γ on Updates from S5 to S6

Scenario: Agent transitions from S5 (action right) to S6. Reward R(S6) = −1. Max Q-value in S6 is Q(S6, up) = 2.0. Stored Q(S5, right) = 1.2, learning rate α = 0.1. Compare γ = 0.1 versus γ = 0.9.

Impact of Discount Factor on Future Reward Weight

Discount Factor γ Computation Update Magnitude
γ = 0.1 (low) Q_obs = −1 + 0.1 × 2.0 = −0.8
TDE = −0.8 − 1.2 = −2.0
Q_new = 1.2 + 0.1 × (−2.0) = 1.0		 Large decrease (0.2); future reward has little weight
γ = 0.9 (high) Q_obs = −1 + 0.9 × 2.0 = 0.8
TDE = 0.8 − 1.2 = −0.4
Q_new = 1.2 + 0.1 × (−0.4) = 1.16		 Small decrease (0.04); future reward heavily weighted

A higher γ makes the robot more tolerant of short-term negative rewards when future rewards are promising, because the future gain (2.0) is weighted more heavily in the Bellman equation. This encourages the agent to take actions with good long-term payoff, even if the immediate reward is negative.

Episodes and Convergence

Episode

Episode: One complete run from a start state to a terminal state (goal or failure), during which the agent takes a sequence of actions and receives a sequence of rewards.

Episode Structure:

  • Starts: Agent at a starting cell (fixed or randomly chosen)
  • Progresses: Agent takes actions, receives rewards, transitions between states
  • Ends: Agent reaches a goal state (e.g., +10 reward) or failure state (e.g., −10 penalty)
Why Multiple Episodes Are Necessary

Single Episode Insufficiency: After just one episode, Q-values are unstable and inaccurate because the agent has seen only one path and limited rewards.

A common mistake is assuming Q-values are correct after a single run. Early Q-values reflect only the rewards encountered in that one episode, not the true long-term value of state-action pairs. For example, if the agent hasn't discovered the goal (+10) yet, it only knows about intermediate negative rewards (−1, −2, −1) and its Q-values will be pessimistic.

Learning Over Multiple Episodes and Convergence

Convergence: As the number of episodes increases, Q-values stabilize and approach their true values—the expected return of each state-action pair under the optimal policy.

Mechanism of Convergence:

  • Each episode gives the agent more experience and more diverse paths through the state space
  • The agent may try different actions (exploration) and discover new paths
  • Each new experience updates Q-values toward the truth via the Bellman update
  • Over many episodes, inaccurate estimates are corrected repeatedly
  • Eventually, Q-values stabilize and stop changing significantly

Learning Completion: When Q-values stop changing much across episodes, the agent has learned the optimal policy. From any state, the agent then knows exactly which action leads to the highest total reward by selecting the action with the maximum Q-value.
