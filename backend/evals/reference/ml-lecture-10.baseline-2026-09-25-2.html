Definition and Core Components

Reinforcement Learning

Reinforcement Learning (RL): Learning what to do (which action to take) based on rewards and punishments received from the environment.

RL is one of three branches of machine learning, distinct in that it maps actions to maximum reward rather than inputs to outputs (supervised) or discovering hidden patterns (unsupervised).

Think of RL like a pet learning tricks for treats. The pet (agent) tries different behaviors in its environment (jumping, rolling, sitting). When it does the right thing, it gets a treat (reward). Over time, it learns which behaviors lead to treats and which don't — without anyone showing it how.

The Five Core Components
  • Agent: The learner (e.g., a robot)
  • Environment: The world the agent interacts with (e.g., a grid, game board, physical space)
  • Action: What the agent can do (e.g., move up, down, left, right; press a button)
  • State: Where the agent is; a snapshot of the environment (e.g., a specific cell in a grid)
  • Reward: Feedback signal indicating how good or bad an outcome is (positive for good, negative for bad, zero for neutral)

The "No Teacher" Principle

No Correct Path Given

Core insight: The agent receives no instructions, no map, and no answer key — only feedback signals from outcomes.

Instead of being told "take this path," the agent:

  • Explores an unknown environment on its own
  • Takes actions and observes the reward or penalty it receives
  • Gradually learns which actions lead to better outcomes
  • Improves by accumulating rewards over time, not by following a preset solution

In a typical scenario, the agent might receive small feedback signals along the way ("warmer" = small positive reward; "colder" = small negative reward) and major outcomes at the goal ("candy" = large positive reward; "lemon" = large negative reward/penalty). The agent uses all of these to refine its decisions.

When to Use RL

Applications and Problem Characteristics
Application Why RL Fits
Self-driving cars No "correct" steering label for every situation; the right action depends on context
Game AI (AlphaGo, Chess) Opponent adapts; no fixed answer key exists
Robot navigation Environment is unknown or changing; the robot must learn in real time
Recommendation systems User feedback is sequential, not one-shot; recommendations improve based on reactions

All these problems share one trait: the correct action is not labeled in advance, but you do have access to feedback signals that tell you how well you did.

The Exploration-Exploitation Dilemma

Core question: Should I do what I already know works (exploit), or try something new that might be better (explore)?

  • Exploitation: Choosing the greedy action—the one with the highest known value. Safe, reliable based on past experience.
  • Exploration: Choosing randomly or trying something untested. Risky, but the only way to discover better paths the agent has not yet encountered.

This dilemma is central to RL: you must balance learning from what you know (exploitation) with discovering new possibilities (exploration). Too much exploitation and you get stuck in local optima; too much exploration and you waste time on bad actions. Q-Learning manages this through its behavior policy.

Value Functions and Q-Learning

Overview
  • What: Introduces the value-based approach to RL — assigning numbers to states and state-action pairs to represent their long-term value, which the agent then learns and uses to make decisions.
  • How it breaks down:
    • Value Functions — what state values and Q-values represent and how they differ
    • The Q-Table — how Q-values are organized and accessed during learning and decision-making
  • Takeaway: Q-Learning works because it separates the problem of "what is each state-action pair worth?" from "what action should I take?" — the algorithm updates the Q-table over time until the values are accurate enough to produce an optimal policy.

Value-Based Methods

Q-Learning as a Value-Based Algorithm

Q-Learning: A value-based reinforcement learning algorithm that learns a value function (Q-values) to determine the optimal policy.

In value-based methods, the algorithm learns to estimate how good each action is in each state. Once these estimates are accurate, the optimal policy emerges naturally: always pick the action with the highest estimated value.

The flow: Value function (learned over many steps) → inputs agent and state → outputs Q-value for each action → Policy (greedy selection of max Q-value) → determines total reward achieved.

Value Functions

State Value V(s)

State value V(s): A number representing how good it is to be in a given state s, assuming the agent acts optimally from that state forward.

V(s) tells you the long-term reward you can expect starting from state s. A high V(s) means that state is desirable; a low or negative V(s) means it should be avoided.

State-Action Value Q(s,a)

State-action value Q(s,a): A number representing how good it is to take a specific action a in a given state s, assuming the agent acts optimally after that first action.

Q(s,a) is richer than V(s): it tells you not just whether a state is good, but which of the available actions in that state is best. The agent's policy is then simply "in state s, pick the action a that maximizes Q(s,a)".

Q-Learning learns Q-values, not state values.

Aspect V(s) Q(s,a)
What it represents Value of being in state s Value of taking action a in state s
Dimensions One value per state One value per state-action pair
Used to decide actions? Indirectly; still need to know which action leads where Directly; pick the action with max Q

The Q-Table

Q-Table Structure and Initialization

Q-table: A two-dimensional table with rows for states and columns for actions, storing Q(s,a) values for each state-action pair.

Each cell Q(s,a) is updated iteratively as the agent gains experience. At the start, Q-values can be initialized arbitrarily (zeros, random numbers, or heuristic estimates).

Even if initialized incorrectly, the Q-Learning algorithm will correct the values over time as the agent accumulates rewards and feedback. The initialization is just a starting point.

Example Q-table for a grid with 3 states and 4 possible actions:

Q Left Right Up Down
S1 0.5 −1.0 2.1 0.75
S2 0.3 1.2 0.8 −0.5
S3 −1.0 0.9 2.5 0.6

The Q-Learning Algorithm and Updates

Overview
  • What: The concrete, step-by-step process of how Q-Learning updates its Q-values based on observed rewards and how discount factors and learning rates control that update.
  • How it breaks down:
    • The Bellman Equation — the fundamental formula linking current and future rewards
    • Temporal Difference Error — how much the observed value differs from the expected value, which drives learning
    • The Update Rule — how the learning rate scales the error and adjusts the Q-value
    • Effect of the Discount Factor — how gamma tunes the agent's tolerance for short-term losses
    • Episodes and Convergence — why one episode is not enough and how Q-values converge over many episodes
  • Takeaway: Q-Learning's update rule (Q ← Q + α × TDE) is simple but powerful: it nudges the Q-table toward the true value every time the agent acts, and the algorithm guarantees convergence to the optimal Q-values if allowed enough episodes and exploration.

The Bellman Equation

Observed Q-Value and the Bellman Equation

Bellman Equation for observed Q-value

Q_{\text{observed}}(s,a) = R(s') + \gamma \max_{a'} Q(s', a')
  • Q_observed(s,a): The value of taking action a in state s, as estimated from this single observed transition
  • R(s'): The immediate reward received upon arriving in the next state s'
  • γ (gamma): Discount factor; how much future rewards are valued relative to immediate rewards
  • max_a' Q(s', a'): The best Q-value available from the next state s'

The Bellman equation encodes the key insight of Q-Learning: the value of an action is not just its immediate reward, but the immediate reward plus the best future you can do from where it takes you.

Like choosing a job: the value of a job is not just the salary today (immediate reward), but the salary plus the career growth and opportunities it opens up (future value). A lower-paying job that leads to better future opportunities might have higher total value.

Discount Factor γ (Gamma)

Discount factor γ: A number between 0 and 1 that determines how much the agent values future rewards relative to immediate rewards.

  • γ = 0: Robot only cares about immediate reward; future is irrelevant. Leads to greedy, short-sighted decisions.
  • γ = 0.5: Future rewards matter half as much as immediate rewards. Mild preference for immediate gains.
  • γ = 0.9: Future rewards matter significantly, but slightly less than today. Balanced perspective.
  • γ = 1: Robot values future rewards equally to immediate rewards. Maximizes total long-term reward; ignores time.

Higher γ makes the agent more tolerant of short-term negative rewards when future rewards are promising. A robot with γ = 0.9 is willing to accept a loss today if it leads to a big gain tomorrow; one with γ = 0.1 is not.

Temporal Difference Error

Temporal Difference Error (TDE)

Temporal Difference Error: The gap between what the agent observed (Q_observed) and what it previously believed (Q_expected), which drives the learning update.

Temporal Difference Error

\text{TDE} = Q_{\text{observed}}(s,a) - Q_{\text{expected}}(s,a)
  • TDE > 0: The observed value was better than expected; the Q-value estimate was too low.
  • TDE < 0: The observed value was worse than expected; the Q-value estimate was too high.
  • TDE ≈ 0: The estimate was accurate; no large update needed.

The TDE is the "error" that signals how much to correct the Q-value. Large errors → large updates; small errors → small updates.

Worked Example: Computing TDE

Agent in state S1, takes action down, arrives at S4.

Given Value
Q_expected(S1, down) 0.75 (from Q-table)
R(S4) −1 (immediate reward at S4)
max_a Q(S4, a) 1.5 (best action from S4)
γ 0.1
Q_{\text{observed}}(S1, \text{down}) = -1 + 0.1 \times 1.5 = -0.85
\text{TDE} = -0.85 - 0.75 = -1.6

Interpretation: The agent expected Q(S1, down) = 0.75, but the observed value was −0.85. The negative error of −1.6 signals that the estimate was too optimistic; the true value is worse.

The Q-Learning Update Rule

Q-Value Update Rule

Q-Learning Update Rule

Q(s,a) \leftarrow Q(s,a) + \alpha \times \text{TDE}
  • Q(s,a): The Q-value being updated
  • α (alpha): Learning rate or step size; controls how much of the error to apply in each update
  • TDE: Temporal Difference Error (calculated as shown above)

This update rule is the core of Q-Learning and must be memorized. The exam will ask you to compute a new Q-value given the old Q-value, the observed reward, discount factor, and learning rate.

How α controls learning:

  • α = 0: No learning; Q-values never change.
  • α = 0.1: Slow, cautious learning; take 10% of the error each step.
  • α = 0.5: Moderate learning; take 50% of the error each step.
  • α = 1: Aggressive learning; fully trust the observation and replace Q-value immediately (rarely used).

Lower α is safer when the environment is noisy (one observation might be a fluke); higher α converges faster in stable, clean environments.

Worked Example: Updating Q(S1, down)

From the previous TDE example, apply the update rule with α = 0.1:

Q(S1, \text{down}) = 0.75 + 0.1 \times (-1.6) = 0.75 - 0.16 = 0.59
Step Value
Old Q(S1, down) 0.75
TDE −1.6
Adjustment (α × TDE) 0.1 × (−1.6) = −0.16
New Q(S1, down) 0.75 − 0.16 = 0.59

The Q-value decreased from 0.75 to 0.59, reflecting the negative TDE. The agent learned that going down from S1 is worse than it thought.

Worked Example: Second Transition S4 → S5

Agent moves from S4 (right) to S5:

Given Value
Q_expected(S4, right) 0.75
R(S5) −2
max_a Q(S5, a) 1.7
γ 0.1
α 0.1
Q_{\text{observed}}(S4, \text{right}) = -2 + 0.1 \times 1.7 = -1.83
\text{TDE} = -1.83 - 0.75 = -2.58
Q(S4, \text{right}) = 0.75 + 0.1 \times (-2.58) = 0.49

Even larger error here (−2.58) because the agent was further from the truth. The Q-value dropped more significantly.

Worked Example: Comparing Two Discount Factors

Agent moves from S5 (right) to S6 with two different values of γ.

Given Value
Q_expected(S5, right) 1.2
R(S6) −1
max_a Q(S6, a) 2.0
α 0.1

With γ = 0.1 (low future value):

Q_{\text{observed}} = -1 + 0.1 \times 2.0 = -0.8
\text{TDE} = -0.8 - 1.2 = -2.0
Q(S5, \text{right}) = 1.2 + 0.1 \times (-2.0) = 1.0

With γ = 0.9 (high future value):

Q_{\text{observed}} = -1 + 0.9 \times 2.0 = 0.8
\text{TDE} = 0.8 - 1.2 = -0.4
Q(S5, \text{right}) = 1.2 + 0.1 \times (-0.4) = 1.16

Comparison:

γ Q_observed TDE New Q-value Interpretation
0.1 −0.8 −2.0 1.0 Large decrease; immediate reward dominates
0.9 0.8 −0.4 1.16 Small decrease; future payoff offsets loss

With high γ (0.9), the algorithm recognized that although the immediate reward is −1, the next state has a high value (2.0), so the overall value is positive (0.8). The agent is more tolerant of the short-term loss because it knows good things are coming. With low γ (0.1), the future payoff is nearly ignored, so the outcome looks bad.

Episodes and Convergence

What Is an Episode?

Episode: One complete run from start to goal (or failure), during which the agent takes actions, receives rewards, and updates Q-values.

In the grid example:

  • Episode starts: Robot at a starting cell (e.g., S1) or randomly chosen.
  • Episode ends: Robot reaches the goal (e.g., S9 with reward +10) or hits a failure state (e.g., S8 with reward −10).

One partial episode walked through in the lecture: S1 → (down) → S4 → (right) → S5 → (right) → S6 → ... (not yet finished; robot hasn't reached S8/S9).

Why One Episode Is Not Enough

After just one episode, the Q-values are still wrong or unstable. They have not yet seen the full picture of the environment.

In the example, after one episode:

  • Q(S1, down) = 0.59 — but is this the true value?
  • The robot has not yet discovered the path to the +10 goal.
  • It has only experienced negative rewards (−1, −2, −1).
  • It has not seen what happens from many other states or with other actions.

One episode is a single data point. The robot's estimate of each Q-value is based on limited experience and will be refined as it explores more.

Why Multiple Episodes Are Needed and Convergence

Convergence: As the agent runs more episodes, its Q-values stabilize and stop changing much, eventually reaching their true optimal values.

With each additional episode:

  1. The robot might try different actions (exploration) or refine actions it has tried before.
  2. It might discover better paths it has never taken.
  3. It updates Q-values closer to the truth based on new observations.
  4. Eventually, Q-values converge (stop changing much).

When Q-values stop changing significantly across episodes, learning is done. At that point, the robot has learned the optimal policy: from any state, it knows exactly which action leads to the highest total reward.

Convergence is not instantaneous. It depends on how many states and actions exist, how much exploration happens, and the learning rate α. A small α converges slowly but smoothly; a large α converges fast but may oscillate.
